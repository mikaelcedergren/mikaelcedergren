# mikaelcedergren.com

Mikael Cedergren's personal portfolio + blog, rebuilt as an **Angular 22 SSG app** — prerendered to
fully static HTML and served by a small Express server on the Mac mini, the **same architecture as
bitsize.me / faunapoolen.se**. English only.

## Run

```bash
pnpm install            # Angular 22 + express + @mikaelcedergren/cx-framework
pnpm dev                # ng serve at http://127.0.0.1:4250
pnpm build              # scripts/sitemap.mjs, ng build (prerender) -> dist/browser, then scripts/flatten.mjs
pnpm build:release      # internal staged build used by the shared release command
pnpm start              # release-aware server at http://127.0.0.1:3050 (HOST/PORT env; health: /healthz)
```

Always-on service: `launchd/com.mikaelcedergren.server.plist` (port `3050`, RunAtLoad + KeepAlive),
fronted by nginx. Publish production content with:

```bash
node ../server-ops/bin/site-release.mjs --site mikaelcedergren --apply
```

The release and rollback behavior is owned by the root
[`SERVER-STANDARD.md`](../SERVER-STANDARD.md).

## Architecture

Angular 22 standalone, prerendered to static HTML (`angular.json` -> `outputMode: "static"`; every
route `RenderMode.Prerender`), served as plain files by Express via the shared server library
(`../../server-ops/lib/site-server.mjs`) — no SSR at runtime.

```
src/
  index.html             <head>: favicon, fonts; <mc-root>
  app/
    app.component.*       shared chrome (bottom nav menu + logo), wraps <router-outlet> in <main>
    app.routes.ts         route + per-page SEO source of truth
    app.routes.server.ts  { path: '**', renderMode: Prerender }
    app.config.ts         router + client hydration + SeoTitleStrategy
    shared/seo.ts         SeoTitleStrategy: per-page title/desc/canonical/OG/Twitter/JSON-LD (single locale)
    pages/**              one component per page; owned editorial HTML rendered via [innerHTML]
public/assets/**          runtime images and documents copied to dist/assets
public/{robots.txt,sitemap.xml}  GENERATED by scripts/sitemap.mjs (both are in angular.json's assets allow-list)
scripts/sitemap.mjs       pre-build: reads data.seo.path from app.routes.ts (skips noindex) -> public/sitemap.xml + robots.txt
scripts/flatten.mjs       post-build: <route>.html/index.html -> flat <route>.html (local or staged output)
server/index.mjs          release-aware static server (shared lib; caching, /healthz, retained chunks, 404)
```

### URLs (unchanged from the legacy site)

- **Sections** at `<dir>/index.html`: `/about/`, `/concepts/`, `/resume/`, `/blog/`.
- **Blog posts** are literal `.html` files: `/blog/posts/<slug>.html` (Angular prerenders
  `<route>/index.html`, `scripts/flatten.mjs` flattens to a flat file).
- Home at `/`.

## Content source of truth

The **Angular app (`src/`) is the source of truth.** Edit pages directly in `src/app/pages/**`.
Content components render their owned HTML through `[innerHTML]` so editorial markup survives the
Angular compiler without a second content pipeline.

## Framework integrity

Cortex is the source of truth; `cx-framework` is its packaged contract; this portfolio is only a
consumer. All colour, type, spacing, radius, measure, and breakpoint values come from framework
tokens; site styles only arrange them.

- Never modify, reference, fork, or optimise Cortex or `cx-framework` from this repository.
- Consumers adapt forward. Never preserve an old contract with compatibility layers, aliases,
  wrappers, redirects, overrides, or temporary framework hacks.
- If the framework is missing something, document it under **🚨 Cortex Action Required** and stop;
  never recreate it locally.
- Prefer simpler architecture and deletion over preserving behaviour. Keep one implementation and
  remove verified dead, duplicate, obsolete, compatibility, legacy, and deprecated code.
- Evidence beats assumptions: uncertain removals are reported, not guessed.
- Add a shared abstraction only when it clearly simplifies today's system. Optimise for five-year
  maintainability, not today's convenience.
